乡村智能问答系统 · 产品需求文档

面向村干部及基层工作人员的 Web 端智能问答工作台：把官方政策和办事流程沉淀为可信赖的知识库，让基层人员在接待村民咨询时"一问即答、答有依据、答不了可闭环"。

1背景与目标

为什么做、为谁做、做到什么程度算成功。

1.1 已确认的关键决策（来自需求沟通）

决策项结论对需求的影响
目标用户村干部 / 基层人员（工作辅助工具，帮他们答复村民、查政策依据）系统不直接面向村民提问；核心场景是"接待中的工作台"
内容领域村务与办事指南 + 综合生活服务知识库分类、示例内容围绕这两类组织；不覆盖深度农技咨询 P1 再评估

1.2 问题链与产品决策

观察到的问题（定性，来自建设方描述，未做量化调研 假设）：

  • 村民咨询高频发生在村委日常接待（办事流程、惠民政策、生活服务），基层人员难以全部掌握，常需翻文件、电话请教乡镇，答复慢；
  • 上级政策文件多、更新快，不同干部答复可能出现口径不一；
  • 答复经验存在个人脑子里，人员流动导致能力流失，新人上手慢。

→ 产品决策：做一个面向基层工作人员的 Web 问答工作台，答案统一锚定由管理方维护的官方知识库，答不了的问题自动记录并由管理员补充，形成"越用越全"的闭环。

→ 系统定位（已确认）：本质上是一个"企业知识库级别"的系统——村级组织的官方知识库 + 智能问答界面。轻量务实：部署在村委会办公电脑、通过大模型 API 接入、自建账号体系，不对接政务平台，不按"政务大系统"的标准做重。

1.3 目标（以可观察行为表述，不设虚构指标）

  • 对知识库已覆盖的问题，工作人员一次提问即可获得带官方依据的答案，当场答复村民，无需翻查文件或电话请示；
  • 同一问题在全村/辖区范围内口径一致（同一知识来源、同一版本）；
  • 暂时答不了的问题被自动记录为未答问题，管理员补充后即可回答（可观察：未答问题清单随使用递增、处理后命中率提升）；
  • 新入职/新轮岗人员可通过自助提问完成业务熟悉，不依赖老同志传帮带。

2产品契约

一句话说清谁、在什么时刻、来做什么、做到什么算完成、凭什么信任它。

要素定义
主要用户村干部及基层工作人员：村两委成员、网格员、驻村工作队员、便民服务窗口人员（下文统称工作人员）
核心任务在接待村民咨询的现场，快速获得有官方依据、口径统一的标准答案，并据此答复村民
触发时刻村民当面/电话/微信提出咨询，工作人员不能立即给出准确答复（或需要确认政策依据、最新口径）
完成证据工作人员在系统内提问后，得到带引用来源卡片的答案（含条目标题、依据文件、发布单位、更新时间），可据此向村民复述
共享对象① 知识条目：管理员维护、全体工作人员消费；② 问答记录：工作人员产生、管理员复盘（用于发现知识缺口）
信任基础所有答案必须锚定"已发布"的官方知识条目并展示来源；无法可靠回答时明确说"暂无可靠答案"并给出转办建议，绝不编造答案——这是本系统不可妥协的底线规则（详见 6.1）

3范围

P0 = 最小但完整的一次问答闭环，外加它的恢复路径。

3.1 P0 最小闭环

  1. 进入：管理员创建账号并下发；工作人员用账号登录系统（FR-05）；
  2. 备料：管理员录入并发布首批官方知识条目（FR-03，上线前置条件；内容由管理员录入——已确认，见 8.1；首批内容量目标实施期确认 TBD）；
  3. 主流程：工作人员用自然语言提问（FR-01）；
  4. 完成证据：命中时，返回带引用来源的答案，工作人员据此当场答复村民；答案与记录均留在"问答记录"中可回溯（FR-02）；
  5. 恢复路径：未命中时，明确提示"暂无可靠答案"+ 相关条目 + 转办建议，该问题自动进入"未答问题清单"（FR-01 未命中规则 → FR-04）；
  6. 闭环：管理员处理未答问题、补充并发布条目，此后同类问题可回答（FR-03 / FR-04）。
登录、账号管理虽然常规，但在本项目中参与核心闭环（政务实名使用与留痕要求），故纳入 P0，但仅做轻量实现（见 FR-05），不做组织架构、多级审批等重功能。

3.2 P1（首版之后的增强，本期不承诺）

  • 常用问题收藏与快捷提问模板；
  • 数据看板：提问量、命中率、高频未答问题、条目"无用"反馈排行；
  • 移动端自适应（Web 响应式，非独立 App）；
  • 敏感类别/关键词库由管理员自助维护（P0 使用内置默认类别，见 6.3）；
  • 问答记录导出、乡镇—村多级组织与知识库分区、条目批量导入。

3.3 明确不做（本期排除，避免范围争议）

  • 村民直接提问的入口（村民仅通过工作人员间接受益；村民端列为后续迭代候选 TBD）；
  • 在线办事办理（本系统只回答"怎么办"，不承接"替你办"，不与审批系统对接）；
  • 独立 App / 小程序（本期仅 Web）；
  • 与政务统一身份认证、政务审批等既有平台的对接（已确认自建账号，见 8.1）；
  • 主动推送、智能外呼、消息通知体系；
  • 深度农技咨询（病虫害诊断等，属专业农技服务范畴 假设，P1 视试点效果再评估）。

4角色与对象模型

两类角色、三个核心对象，一张权限矩阵说清楚。

4.1 角色定义

  • 工作人员：提问、查看自己的问答记录、对答案反馈"有用/无用"。含村两委成员、网格员、驻村队员、窗口人员；
  • 管理员：知识条目的增改与发布/下线、未答问题处理、账号管理、查看全部问答记录与反馈。假设 由村委会指定 1–2 名（如村文书、便民服务负责人），具体人选 TBD（单村试点，见 8.1）。

4.2 权限矩阵（全文档唯一定义，功能节引用不再重复）

能力工作人员管理员
提问、查看答案与引用来源✓✓
查看问答记录仅本人全部（复盘用）
删除问答记录—（留痕要求，任何人不可删，见 6.4）—
答案反馈（有用/无用）✓✓
知识条目新增/编辑—✓
知识条目发布/下线—✓

4.3 核心对象与状态

① 知识条目（唯一答案来源）

草稿 —发布→ 已发布 —手动下线→ 已下线 —重新发布→ 已发布
已发布 —到达失效日期（自动）→ 已过期（自动下线） —管理员更新后重新发布→ 已发布
  • 编辑不改变状态：已发布条目可直接编辑保存，保存后仍为已发布，系统记录修改人与时间（留痕）；
  • 到期自动下线而非仅提示：过期政策继续被引用的风险大于知识短暂缺失的风险（产品判断）；管理端以"已过期"标记提醒管理员更新；
  • 草稿、已下线、已过期条目一律不参与问答。

② 问答记录

  • 回答状态：已回答（命中） / 未命中 / 超出范围（敏感）；
  • 反馈状态：未评价 / 有用 / 无用（仅"已回答"记录可反馈，反馈后可更改）。

③ 未答问题（仅由"未命中"记录生成，敏感类除外）

  • 状态：待处理 → 已补充（新条目发布后自动标记，并双向关联）/ 已关闭（必填关闭原因）；
  • 相似问题自动聚合计数，管理员可对误聚合的问题手动拆分（已确认，见 8.1）；聚合算法口径 假设 由技术设计阶段确定。

本文档的主体。每个模块覆盖：目的 / 触发 / 处理规则 / 结果与状态 / 字段 / 异常。交互重的 P0 模块内嵌可点击演示（演示数据均为虚构示例，仅用于评审行为，不代表最终视觉稿）。

FR-01 智能问答（核心）

目的：工作人员用自然语言提问，立即获得有官方依据的标准答案，支撑当场答复村民。

触发：任何已登录工作人员，在提问框输入问题并提交，或点击示例/收藏问题。

处理规则

  1. 系统仅基于"已发布"状态的知识条目组织答案（草稿/已下线/已过期不参与）；
  2. 命中（存在高相关已发布条目）时，答案卡片固定包含三部分：
    • ① 答案正文：直接回应问题，分点陈述；
    • ② 引用来源卡片：条目标题、依据文件名、发布单位、条目最后核实时间；
    • ③ 时效提示行：如"以上内容更新于 {时间}，请以最新官方发布为准"。
  3. 未命中（无高相关已发布条目，或依据不足以给出可靠结论）时，展示兜底卡片：
    • 明确文案"暂无可靠答案"（不允许给出模糊猜测）；
    • 最多展示 3 条相关已发布条目（如有）供工作人员自行查看；
    • 转办建议：建议向对应的乡镇部门咨询（按问题类别给出建议部门 假设：初始按分类映射，如惠民政策→民政/社保窗口）；
    • 提示"该问题已自动记录，管理员将补充知识条目"。
  4. 敏感问题拦截：命中敏感类别（见 6.3）时不作答，展示建议渠道（司法所/卫生院/纪检监察等）与"本回答不构成专业意见"提示。敏感问题生成"超出范围"记录，不进入未答问题清单（避免污染知识缺口列表）；
  5. 输入框提示文案："请勿输入村民姓名、身份证号等个人敏感信息"（合规要求，见 7.2）。

结果与状态变化：每次提问生成一条问答记录（已回答 / 未命中 / 超出范围）；未命中记录自动进入未答问题清单（FR-04）。

字段

字段规则
问题文本必填，≤500 字，超出前端即时提示并阻止提交
答案正文系统生成，仅命中时存在
引用来源系统生成，随答案展示，必含四个要素（见规则 2）
反馈未评价（默认）/ 有用 / 无用，仅工作人员本人可评

异常

  • 输入为空：提交按钮不可用；
  • 知识库为空（首批条目未发布）：空态提示"知识库正在建设中"，提问仍可用，全部进入未命中流程（保证未答问题照常记录）；
  • 答案生成失败/超时：展示重试按钮，不产生半成品问答记录（重试成功才落库，见 6.5）；
  • 同一问题短时间重复提问：正常受理并各自记录（不做合并，由未答问题清单聚合）。

FR-02 问答记录与反馈

目的：工作人员可回溯历史问答（村民追问时复查口径）；反馈数据支撑管理员发现过期、错误条目。

触发：工作人员进入"问答记录"页（演示中为问答界面的右侧栏）。

处理规则

  1. 列表按提问时间倒序：问题摘要、回答状态（已回答/未命中/超出范围）、反馈状态、提问时间；
  2. 点击记录查看完整答案与引用来源；
  3. 反馈：仅"已回答"记录可评"有用/无用"，评价后可更改；"未命中"记录不提供反馈（其价值由 FR-04 承接）；
  4. 记录不可删除、不可编辑（政务留痕要求，见 6.4）；
  5. 管理员可查看全部人员的记录与反馈，用于复盘（权限见 4.2 矩阵）。

异常：无记录时展示空态并引导提问（演示右侧栏初始状态即空态）。

FR-03 知识库管理（管理员）

目的：保证"答有依据"——管理员维护官方知识条目，控制发布、时效与下线。知识库质量直接决定系统可信度，故与问答同为 P0。

触发：管理员登录后进入"知识库管理"。

处理规则

  1. 新增：填写字段（见下表），保存为草稿；
  2. 发布：草稿/已下线/已过期条目均可发布，发布时校验必填字段；发布即时对全体问答生效；
  3. 编辑：任何状态均可编辑；已发布条目保存后保持已发布状态，记录修改人与时间（留痕）；
  4. 下线：仅已发布条目可下线；下线原因必填（预设选项：政策已更新 / 内容有误 / 其他 + 补充说明）；
  5. 有效期：条目可填失效日期；到期自动下线并在管理端标为"已过期"，提示管理员更新；
  6. 重复提示：新增条目与已有已发布条目标题高度相似时，提示"是否为原条目的更新版本"，引导编辑原条目而非新建重复条目（口径唯一）；
  7. 留痕：新增、编辑、发布、下线均记录操作人、时间、动作，管理员可查（操作日志）。

异常

  • 标题重复：阻断并提示编辑原条目；
  • 无依据文件：阻断保存与发布（知识库仅收录有官方依据的内容，草稿也不例外）。

FR-04 未答问题处理（管理员）—— 系统自我修复闭环

目的：未命中问题是最真实的知识缺口信号。管理员据此补充知识库，使系统"越用越全"。

触发：管理员进入"未答问题"列表。

处理规则

  1. 列表展示：问题、发生时间、聚合次数（相似问题合并计数 假设）、状态（待处理 / 已补充 / 已关闭）；
  2. 去补充：跳转新增条目表单并带入该问题作为参考；保存草稿后条目仍为草稿，条目发布后该未答问题自动标记"已补充"，并与新条目双向关联；
  3. 关闭：不属于服务范围的问题（如"帮我写诉状"）可关闭，关闭原因必填（预设选项：超出服务范围 / 属线下办理事项 / 其他 + 说明）；
  4. 敏感类"超出范围"记录不进入本清单（见 FR-01 规则 4）；
  5. 聚合与拆分：相似的未命中问题自动聚合计数；管理员可对误聚合的问题手动拆分，拆分后各自独立计数（已确认，见 8.1）。

异常：清单为空时展示空态"暂无待处理问题"。

FR-05 账号与登录（轻量）

目的：满足政务实名使用与留痕要求；不追求复杂组织能力。

处理规则

  1. 账号由管理员创建：姓名、所属村/部门（仅作展示信息 假设，本期单组织部署，无组织树）、角色（工作人员/管理员）；
  2. 初始密码由系统生成并交管理员线下转交，首次登录强制修改密码 假设；
  3. 登录方式：账号 + 密码；连续 5 次失败临时锁定 15 分钟 假设（阈值可在部署时调整）；
  4. 管理员可为人员停用账号（人员离职/轮岗）、重置密码；停用账号的问答记录保留（留痕）；
  5. 不对接政务统一身份认证：使用本系统自建账号体系（已确认，见 8.1）；账号管理能力保留在本模块。

6共享规则与异常（唯一定义，各功能节引用）

6.1 引用溯源规则（信任底线）

  • 每条"已回答"答案必须携带引用来源卡片，四要素缺一不可：条目标题、依据文件名、发布单位、最后核实时间；
  • 无来源不构成答案：依据不足时一律走"未命中"兜底，禁止输出无引用的结论性内容；
  • 每条答案附"以最新官方发布为准"的时效提示。

6.2 未命中兜底规则

  • 兜底三要素：明确"暂无可靠答案" + 相关条目（≤3 条）+ 转办建议；
  • 兜底必须提示"该问题已自动记录"，未命中记录自动进入未答问题清单（FR-04）；
  • 转办建议按分类映射到建议部门 假设，映射表由管理方在实施期确认 TBD。

6.3 敏感问题规则

  • P0 内置默认类别：① 涉法涉诉（起诉、纠纷裁决等）② 医疗诊断 ③ 信访举报 ④ 涉及资金往来的个人决策（如借贷担保）；
  • 命中敏感类别：不作答、给出对应建议渠道（司法所 / 12348 法律援助 / 卫生院 / 纪检监察渠道）+"本回答不构成专业意见"提示；
  • 记录状态"超出范围"，不进入未答问题清单；管理员可按月导出查看（是否需上报处置流程 TBD）；
  • 敏感类别/关键词的自助维护为 P1（P0 固化默认清单）。

6.4 留痕与保留规则

  • 问答记录、知识库操作（新增/编辑/发布/下线）、账号操作（创建/停用/重置）全部留痕，含操作人、时间、动作；
  • 任何角色不可删除/篡改问答记录；
  • 保留期限：1 年（已确认，见 8.1）；到期后的归档导出与清除细则实施期确认 TBD。

6.5 服务异常共享规则

  • 答案生成、保存等操作失败时统一展示重试入口；失败不落库，成功才生成记录（防止半成品记录污染留痕与未答清单）；
  • 本 PRD 不承诺具体性能指标（响应时间、并发数）TBD，由技术设计阶段与部署环境确定后补充验收口径。
